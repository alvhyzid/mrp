# FABRIX UX Decision Records

## Purpose

Use decision records for decisions that affect more than a single local implementation.

## ID format

`UX-YYYY-NNN`

Example:

`UX-2026-001`

## Template

### Decision ID

UX-YYYY-NNN

### Title

Short decision title.

### Status

- Proposed
- Approved
- Rejected
- Superseded

### Context

What problem or ambiguity triggered the decision?

### Evidence

Reference:

- AS-IS audit
- Carbon guidance
- repository findings
- business requirement
- user flow
- accessibility requirement

### Decision

State the chosen behavior.

### Carbon basis

Identify the Carbon component/pattern/guidance used as the baseline.

### FABRIX-specific rationale

Explain what Carbon cannot decide and why FABRIX needs this rule.

### Alternatives considered

List alternatives and why they were rejected.

### Scope

Which modules/pages/components are affected?

### Non-goals

What this decision does not change.

### Acceptance criteria

Measurable conditions for implementation acceptance.

### Implementation notes

High-level only. Do not turn the decision record into a code plan.
