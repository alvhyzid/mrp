# FABRIX AGENT OPERATING MODEL
## Recommended sequence for the segmented ChatGPT architecture

### Phase 1 — Guardian setup
Create one Architecture Guardian chat and give it all global governance plus current approved baselines.

### Phase 2 — Segment chats
Create one chat per segment using the registry and file matrix. Start with Sales as the already-developed reference segment.

### Phase 3 — Segment work
Each segment maintains deep domain reasoning without carrying the entire project conversation.

### Phase 4 — Cross-domain review
Whenever a segment creates/changes a contract, entity ownership, state machine, or UX navigation, route the proposal to Architecture Guardian.

### Phase 5 — Technical handoff
Only approved business architecture goes to Opus for technical design.

### Phase 6 — Implementation
Claude Code implements only from approved technical instructions and registered tasks.

### Phase 7 — Certification
QA/Release verifies and records evidence.

### Phase 8 — Memory update
After acceptance:
- update canonical architecture
- update ADR
- update entity/state/contract registries
- update task status
- update segment handoff
- update project status summary

### Key principle
Conversation is temporary working memory. Canonical files are project memory.
